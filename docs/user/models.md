# 模型与服务

Aura 不带模型，你需要接入自己的模型服务。在“设置 → 模型”里管理。

## 添加服务

- 选一个服务类型（如 DeepSeek，或任何 OpenAI 兼容接口），填地址和 API Key。连接的接口格式可以选 OpenAI Responses、OpenAI Chat Completions 或 Anthropic Messages。API Key 只保存在 Windows 凭据管理器里，界面上不再显示原文，也不写进 Aura 的任何文件。
- 一个服务下可以有多个连接（不同的 Key 或地址），可以指定默认连接。
- 保存后，Aura 列出这个服务提供的模型；也可以手动添加模型。
- 并非每个服务商都实测过，见[已知限制](limitations.md#已知限制)。

## 模型设置

每个模型可以设置：

- **会话默认思考程度**：新会话用这个模型时的思考档位；“官方默认”表示不指定，由服务决定。
- **图片输入**：接收或不接收。接收时，消息里的图片、截图和视频关键帧会发给这个模型；不接收的模型只收到文字说明。
- 上下文窗口与输出上限：用来判断什么时候需要压缩上下文。上下文窗口一栏显示这个模型实际使用的值；改了以后随“保存 Profile”一起保存，清空则回到目录里的值或默认的 256,000。

## 在会话里选择

输入框下方可以切换这个会话的模型和思考程度。每个会话记住自己的选择；新会话使用设置里的默认值。

## 上下文压缩

对话变长后，Aura 会在下一次请求放不下之前自动压缩：较早的对话由模型总结成一段话（约 3000 字以内，上一次的总结并进新的这段），最近的内容保留原文，压缩一次做完。模型两次都没给出可用的总结时，Aura 用一段简短说明代替，会话照样继续。也可以随时在输入框输入 `/compact` 手动压缩，后面可以附上希望保留的重点。

Aura 按模型服务商回报的真实 token 数估算之后的请求。还没回报过用量的模型，第一次请求先按常用经验粗估：英文和代码约 3 个字符 1 个 token，中文约 1 个字 1 个 token。粗估偏低时，服务商会拒绝过长的请求，Aura 随即压缩后重试；没有可压缩的内容时会暂停并说明是服务商拒绝了请求，不会因此改动模型的上下文窗口。

压缩后，上下文里还有压缩时最近 6 轮的列表（一轮是一个任务，从你提出到完成，每轮列出第一条消息的开头）。被压缩掉的原文没有丢：模型可以按轮列出会话历史、搜索历史内容，并读取任何一条消息、思考、回复或工具调用的原文。

## 网络代理

模型请求和联网工具（网页抓取、HTTP 请求与下载、远程 MCP 连接）都经 Aura 的网络模块发出，默认跟随系统，走不走代理由代理软件的分流规则决定：

- 代理软件开了“系统代理”：公网的 https 请求按域名交给 Windows 代理设置里这台电脑上的代理端口。每次模型请求、每一步工具调用都重新读一次 Windows 的设置；只读取，不改动。
- 代理软件开的是 TUN 模式：域名解析成代理软件自己的地址（如 198.18.x.x），Aura 照常连过去。局域网名字（如 `.lan`、`.local`）仍按内网对待。
- 本机和局域网地址不经代理。

Windows 用的是自动配置脚本（PAC），或者代理在别的电脑上时，Aura 用不了它，直接连接，设置页会说明原因。

要指定代理时，在“设置 → 模型”的网络代理里启用并填写本机代理的协议、地址和端口。启用后，模型请求和联网工具都走它，不再跟随系统。

检查更新用启用的代理；没有启用时用系统代理。
